# Разработка TopDps

TopDps устроен так, чтобы логика конкретного класса и специализации была отделена от общего движка, проверки готовности способностей и интерфейса.

## Структура проекта

```text
Core/           namespace, настройки, база, API-обёртки и логирование
Engine/         общий движок, кнопки, готовность, контекст и combat tracker
Specs/          provider-контракт, определение активного спека и сами специализации
Presentation/   подсветка кнопок и центральные иконки
UI/             страницы настроек и кнопка миникарты
Vendor/         встроенные сторонние или адаптированные визуальные компоненты
Textures/       текстуры аддона
tools/          инструменты сборки, в том числе генератор списка spec-файлов
Bootstrap.lua   инициализация и маршрутизация игровых событий
TopDps.toc      манифест и порядок загрузки файлов
```

## Как работает специализация

`SpecManager` один раз определяет класс и активное дерево талантов, получает provider из `SpecRegistry` и кеширует его. Повторное определение выполняется только при событиях, которые могут изменить специализацию или таланты.

Общий `RotationEngine` не знает ничего о паладине, воине или другом классе. Он получает от provider список приоритетов и проверяет способности через общий `ReadinessService`.

## Добавление нового класса или специализации

1. При необходимости создайте `Specs/<Class>/Common.lua` с общими константами класса.
2. Создайте `Specs/<Class>/<Spec>.lua`.
3. Создайте provider через `TopDps.SpecProvider:Create(...)`.
4. Укажите как минимум:
   - `id`;
   - `classToken`;
   - `talentTab` от `1` до `3`;
   - `categories`;
   - `abilities` со списками `spellIds`;
   - `GetPriority(context)`.
5. Зарегистрируйте provider через `TopDps.SpecRegistry:Register(provider)`.

Пример метаданных:

```lua
local Fury = TopDps.SpecProvider:Create({
    id = "WARRIOR_FURY",
    classToken = "WARRIOR",
    talentTab = 2,
    categories = {
        "bloodthirst",
        "whirlwind",
    },
    abilities = {
        bloodthirst = { spellIds = { 23881 } },
        whirlwind = { spellIds = { 1680 } },
    },
})
```

Один provider класса можно пометить `defaultForClass = true`. Он используется до появления распределённых талантов или когда клиент не позволяет надёжно прочитать дерево талантов.

`SpecProvider` уже содержит стандартные реализации проверки range, ready entries, каталога spell ID/name и других общих операций. Специализация переопределяет только действительно специфичное поведение.

## Автоматическое подключение специализаций

WoW 3.3.5a не умеет во время работы аддона просканировать папку и загрузить новые Lua-файлы: список файлов должен быть известен из `.toc` заранее.

Поэтому список специализаций генерируется автоматически на этапе сборки:

```text
python3 tools/generate_toc.py
```

Генератор сканирует `Specs/<Class>/*.lua`, загружает `Common.lua` первым и обновляет блок между маркерами `TopDps-Specs-Start/End` в `TopDps.toc`.

При создании релиза GitHub Actions запускает генератор автоматически. Отдельная CI-проверка не даст смержить устаревший `.toc` незаметно.

## Где вручную менять ротацию

Текущая эталонная реализация — `Specs/Paladin/Retribution.lua`.

В начале spec-файла находится декларативное описание поддерживаемых способностей. Ниже находится таблица `PRIORITY` — основное место, где можно вручную менять порядок способностей для конкретных режимов. Специальные условия вроде execute, проков, дистанции или типа цели остаются методами этого же provider.

Таким образом, для изменения самой ротации не требуется трогать `RotationEngine`, `SpecManager` или UI.

## Готовность способности и будущий lookahead

`Engine/ReadinessService.lua` отвечает за usability, range и cooldown. В нём уже разделены методы получения остатка cooldown способности и остатка GCD.

Текущий движок намеренно продолжает выбирать только способность, готовую по существующим правилам. Lookahead window в этот рефактор не входит.

В будущем его можно добавить в общий слой готовности/выбора кандидата, сравнивая остаток GCD и cooldown более приоритетной способности. Providers и таблицы ротаций для этого переделывать не потребуется.

## Особенности WoW 3.3.5a

- Аддон рассчитан на интерфейс версии `30300`.
- Стандартная панель настроек аддонов имеет рабочую область примерно `413x429` px.
- В `Core/GameApi.lua` находятся обёртки совместимости для различий API клиента 3.3.5a и отдельных private server сборок.
- Сейчас предполагается использование стандартных панелей действий Blizzard.

## Отладка

Страницу отладки можно полностью скрыть в `Core/Namespace.lua`:

```lua
addon.SHOW_DEBUG_OPTIONS = false
```

При изменении определения способностей или совместимости с WoW API включайте отладочный журнал и проверяйте распознанные ID способностей и текущее состояние рекомендации непосредственно в игре.

## Версионирование и релизы

Проект использует семантическое версионирование.

- Тег и название релиза: `vX.Y.Z`, например `v0.1.1`.
- Архив релиза: `TopDps-X.Y.Z.zip`.
- README, документация и описание релизов ведутся на русском языке.
