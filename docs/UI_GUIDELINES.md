# Правила интерфейса TopDps

Этот документ фиксирует правила для страниц настроек TopDps в `InterfaceOptions` WoW 3.3.5a.

Главный принцип: страница не должна самостоятельно подбирать размеры типовых контролов. Геометрия и интервалы задаются через `UI/OptionsLayout.lua`, а конкретная страница описывает только состав и порядок элементов.

## Источник истины

- Общие размеры, отступы и высоты строк находятся только в `OptionsLayout.Size`.
- Общая логика создания и раскладки типовых элементов находится только в `OptionsLayout`.
- Если один и тот же размер нужен двум и более страницам, он не должен дублироваться локальной константой.
- Локальные размеры допустимы только для действительно уникального элемента конкретной страницы.
- Поведение Blizzard-шаблонов проверяется по FrameXML WoW 3.3.5a, а не по Retail API.

## Геометрия страницы

- Контейнеры строятся относительно фактического размера родителя.
- В `Create()` нельзя полагаться на окончательное значение `GetWidth()`/`GetHeight()` страницы: при первом открытии после `/reload` Blizzard может ещё не рассчитать геометрию.
- Адаптивная геометрия пересчитывается в `ApplyLayout()`.
- `ApplyLayout()` вызывается из `OnSizeChanged` и после первого `OnShow` через отложенный вызов следующего кадра.
- Не смешивать одновременно фиксированную ширину и конфликтующие горизонтальные anchors одного элемента.

## Вертикальная раскладка

- Обычные элементы размещаются последовательно через `CreateCursor()`, `TakeRow()` и `AddGap()`.
- Не использовать цепочки абсолютных координат вида `y = -154`, `y = -198`, `y = -246` для обычной формы настроек.
- Высота scroll-content рассчитывается по фактической позиции последнего элемента.
- Для стандартных промежутков использовать `ROW_GAP`, `SECTION_GAP` и высоты строк из `OptionsLayout.Size`.

## Checkbox

- Использовать `OptionsCheckButtonTemplate`.
- Размер checkbox задаётся в `OptionsLayout.Size`, а не на странице.
- Подпись привязывается к checkbox и центрируется по вертикали.
- Ширина подписи рассчитывается от доступной ширины родителя.
- Кликабельная область должна включать подпись.

## Slider

- Использовать `OptionsSliderTemplate`.
- Сам Blizzard-шаблон имеет фиксированный базовый размер, поэтому итоговая ширина задаётся через `SetWidth()` после получения реальной ширины родителя.
- Левый и правый отступы slider задаются только в `OptionsLayout.Size`.
- Не растягивать slider одновременно двумя горизонтальными anchors поверх его фиксированной ширины.

## Dropdown / ComboBox

- Использовать `UIDropDownMenuTemplate` и `UIDropDownMenu_SetWidth()`.
- Обычный `Frame:SetWidth()` для этого шаблона недостаточен: видимая рамка состоит из отдельных `Left`, `Middle`, `Right` текстур.
- Геометрия dropdown считается централизованно в `OptionsLayout` с учётом особенностей FrameXML 3.3.5a.
- Левая и правая визуальные поправки dropdown не должны использоваться для slider: эти контролы имеют разную внутреннюю геометрию.

## Текст

- Ширина `FontString` рассчитывается от ширины контейнера.
- Многострочному описанию нельзя задавать геометрию, которая фактически ограничивает его одной строкой.
- Для обычного текста использовать `ApplyTextWidth()` и стандартные font objects Blizzard.
- Не фиксировать ширину текста значениями вроде `340`, `365` и т.п. без реальной причины.

## ScrollFrame

- ScrollFrame добавляется только когда содержимое действительно может не помещаться.
- На коротких страницах лишний scrollbar не создаётся.
- Ширина scroll-child пересчитывается от viewport, а не хранится как постоянная ширина страницы.
- Не размещать видимую часть контрола за пределами scroll viewport: она будет обрезана clipping-ом.

## Кнопки и прочие типовые контролы

- Повторяемые размеры кнопок находятся в `OptionsLayout.Size`.
- Если появляется новый тип контрола, который будет использоваться на нескольких страницах, сначала добавить его создание и размеры в `OptionsLayout`, затем использовать на страницах.
- Страница не должна копировать реализацию типового контрола из другой страницы.

## Разделение интерфейсов

Эти правила относятся прежде всего к страницам настроек `InterfaceOptions` (`GeneralOptions`, `RotationOptions`, `DebugOptions` и будущим страницам).

Боевая панель способностей является отдельным UI-модулем. Её нельзя автоматически переводить на layout страниц настроек только ради унификации: общие элементы выносятся туда отдельно, когда это действительно подходит архитектуре панели.

## Проверка новой или изменённой страницы

Перед merge проверить:

1. Первое открытие сразу после `/reload`.
2. Повторное открытие страницы после закрытия окна настроек.
3. Переключение между соседними страницами TopDps.
4. Перенос длинных русских строк.
5. Отсутствие лишнего scrollbar.
6. Одинаковые размеры и интервалы однотипных контролов.
7. Отсутствие локальных magic numbers для типовых checkbox, slider, dropdown и button.
8. Отсутствие обрезания правого края dropdown/slider внутри ScrollFrame.

Если визуальный результат требует изменить общий размер типового элемента, сначала менять `OptionsLayout.Size`, а не подбирать отдельное значение на конкретной странице.
