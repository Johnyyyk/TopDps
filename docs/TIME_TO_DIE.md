# Экспериментальная оценка time-to-die

`Engine/TimeToDieService.lua` оценивает ожидаемое время жизни текущей цели по наблюдаемому темпу потери здоровья. Это эвристика, а не гарантированный прогноз encounter mechanics.

## Контракт

Основной API:

```lua
TimeToDieService:GetEstimate(unit)
```

Результат:

- `nil` — данных недостаточно или текущий тренд недостаточно надёжен;
- `0` — цель уже мертва/имеет нулевое здоровье;
- положительное число — текущая оценка оставшихся секунд.

Rotation provider'ы не должны вызывать сервис напрямую. `ContextBuilder` публикует результат как:

```lua
context.target.timeToDie
```

Поле заполняется только если двойной experimental opt-in для TTD активен. Иначе оно равно `nil`, а накопленная история сервиса сбрасывается.

## Как provider включает TTD

Provider должен явно объявить feature-toggle:

```lua
settings = {
    {
        type = "checkbox",
        key = "useTargetTimeToDie",
        labelKey = "ROTATION_USE_TARGET_TIME_TO_DIE",
        default = false,
        experimental = true,
        experimentalFeature = addon.EXPERIMENTAL_FEATURE_TARGET_TIME_TO_DIE,
    },
}
```

После этого пользователь сначала включает глобальные экспериментальные функции, затем отдельно включает TTD у нужного спека.

Если `context.target.timeToDie == nil`, provider обязан использовать обычную stable-логику. Core не выбирает DoT, execute или spender самостоятельно.

## Алгоритм

Текущая реализация намеренно консервативна:

- новый sample не чаще одного раза в `0.5` секунды;
- если между двумя наблюдениями прошло больше `1.5` секунды, старая история не склеивается с новой и начинается заново;
- рабочее окно — последние `6` секунд;
- оценка не появляется раньше `5` samples и минимум `2` секунд наблюдения;
- скорость потери HP рассчитывается линейной регрессией по всему окну, а не по одной паре точек;
- если скорость потери меньше `0.1%` максимального HP в секунду, оценка считается недостаточно надёжной и возвращается `nil`.

Оценка в секундах вычисляется как текущее здоровье, делённое на модуль отрицательного slope регрессии.

## Когда история сбрасывается

История текущей цели очищается при:

- смене GUID;
- изменении максимального HP;
- откате игрового времени назад;
- разрыве наблюдения больше `1.5` секунды;
- лечении на `2%` максимального HP или больше между samples;
- накопленном неотрицательном тренде здоровья;
- исчезновении/невалидности unit;
- выключении experimental gate.

Разрыв наблюдения особенно важен, потому что `RotationEngine` не строит context, когда ротация заблокирована: например, нет атакуемой цели или выключен режим работы. При возврате к тому же GUID сервис не должен использовать старые samples как непрерывную историю.

Мелкие хилы меньше порога остаются внутри regression window и могут уменьшить скорость падения HP. Если из-за них общий тренд становится неотрицательным, история всё равно сбрасывается.

## Ограничения

TTD не пытается предсказывать:

- иммунитеты и scripted downtime;
- будущие burst-фазы рейда;
- phase transitions;
- forced target swap;
- encounter-specific healing;
- внезапные execute-модификаторы у других игроков.

Combat log намеренно не является источником TTD: чтение фактического UnitHealth учитывает совокупный урон всей группы/рейда независимо от источника.

Сервис хранит историю только текущего unit/GUID. Multi-target TTD history в этот контракт не входит.

## Текущее использование

Demonology и Destruction Warlock используют TTD как экспериментальный уточнитель режима `Проклятие: Авто`.

Если на цели уже есть внешний аналог `Curse of the Elements`, то при известном TTD:

- `TTD > 60 секунд` → выбирается `Curse of Doom`;
- `TTD <= 60 секунд` → выбирается `Curse of Agony`.

Если TTD ещё неизвестен (`nil`), сохраняется прежний fallback: boss-like цель выбирает Doom, обычная цель — Agony. Если внешний magic-vulnerability debuff отсутствует, по-прежнему требуется `Curse of the Elements` независимо от TTD. Ручные режимы Doom/Agony/Elements и `Не предлагать` TTD не переопределяет.

Когда оценка пересекает 60-секундный порог и на цели висит неподходящее собственное damage-curse, требование проклятия снова считается невыполненным, чтобы ротация могла предложить замену.

Переключатель `Учитывать время жизни цели` у Demo/Destro является experimental, появляется только после глобального opt-in и по умолчанию выключен. При выключенном переключателе текущая стабильная логика проклятий остаётся без изменений.

Будущие потребители TTD — другие DoT/execute-спеки вроде Feral Cat, Shadow Priest и Affliction Warlock.

## Тесты

`tools/test_time_to_die.lua` покрывает:

- недостаточный объём samples;
- стабильное снижение здоровья;
- смену GUID;
- заметное лечение;
- неотрицательный тренд;
- изменение maximum HP;
- разрыв наблюдения;
- dead/zero HP;
- invalid unit и отсутствие API.

`tools/test_experimental_features.lua` отдельно проверяет двойной opt-in и валидацию experimental feature-toggle.

`tools/test_warlock_ttd_curse.lua` проверяет TTD-порог Doom/Agony, legacy fallback при `nil`, приоритет `Curse of the Elements`, ручные режимы и замену уже активного damage-curse при изменении оценки.
